# SnapStudio AI

SnapStudio AI turns a product photo into a set of fashion-scene variations, delivered through Cloudinary and managed in a private workspace.

## Local development

1. Install Node.js 22.13+ and npm.
2. Copy `.env.example` to `.env` and set the PostgreSQL, Clerk, and Cloudinary values.
3. Install dependencies with `npm install`. Prisma Client is generated by the `postinstall` script.
4. Apply the schema to a development database:

   ```bash
   npm run db:migrate -- --name init
   ```

5. Start the app:

   ```bash
   npm run dev
   ```

The account must have Cloudinary's `cld_fashion` and `captioning` analysis add-ons enabled, along with the Cloudinary Image Generation add-on. Image Generation is used in reference-guided mode to create a model-wearing-product campaign image from the uploaded product photo. These Cloudinary features can require plan or account activation.

## Environment variables

- `DATABASE_URL`: direct PostgreSQL URL used by Prisma migrations.
- `DATABASE_URL_POOLED`: pooled PostgreSQL URL used by the application runtime when available.
- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`: Clerk application keys.
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`: Cloudinary server-side credentials.

Never commit `.env` or expose `CLERK_SECRET_KEY`, `CLOUDINARY_API_SECRET`, or database credentials in client-side variables.

## Production deployment on Vercel

1. Push the project to a Git provider and import it into Vercel as a Next.js project.
2. Add every production environment variable above in Vercel's **Project Settings → Environment Variables**. Use the direct PostgreSQL URL for `DATABASE_URL` and the provider's pooler URL for `DATABASE_URL_POOLED`.
3. Configure the production Clerk instance with the Vercel deployment domain and add `/sign-in` and `/sign-up` as its sign-in and sign-up routes.
4. Confirm the Cloudinary account has image analysis and Image Generation enabled.
5. Apply the migration to the production database before the first release:

   ```bash
   npm run db:deploy
   ```

   Run this from a trusted deployment/release environment with the production direct database URL configured. Do not run `migrate dev` against production.
6. Deploy from Vercel. Vercel runs `npm install` (which generates Prisma Client) and `npm run build`.
7. Test sign-in, a small image upload, generation, format downloads, and project deletion on the deployed domain.

The generation route requests up to 120 seconds. Current Vercel Function limits allow this on Hobby (up to 300 seconds); verify the limit for your account and project before launch. Keep the generated image calls within this window. The route calls Cloudinary synchronously, so a timeout can leave the project marked failed even if Cloudinary completed work; check project status and the Cloudinary Media Library before retrying an interrupted run.

Before opening the hackathon demo to users, smoke-test a Vercel Preview deployment with production-like Clerk, database, and Cloudinary configuration. Confirm sign-in redirects back to the deployed domain, a generated project persists after reload, and image URLs/downloads work from the deployed hostname.

## Current product scope

Cloudinary AI analyzes the uploaded product and its reference-guided Image Generation API creates editorial scenes intended to show the garment on a selected male or female adult model. Users choose model styling and campaign scenes before generation. Generated assets are stored in Cloudinary and delivered through its CDN; preview and download formats use automatic format/quality and size transformations. The generated image is AI-created, so inspect garment details such as logos, patterns, and text before using it as a definitive catalog representation.
